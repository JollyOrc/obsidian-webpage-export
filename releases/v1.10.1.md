# Webpage HTML Export (Raiders of Arismyth fork) 1.10.1

**Released:** 2026-11-11
**Based on:** upstream Webpage HTML Export 1.9.2 (`78c973d`)

A bug fix: pages no longer lose the output of plugin blocks that draw
after a first child (for example a `dataviewjs` view with a `view.css`).

## Bug fixes

- **Plugin blocks are exported finished** (#12). A page was copied as soon
  as no plugin block was empty. Dataview's `dv.view` puts the view's
  `<style>` into the block before its script runs, so such a block counted
  as rendered at once, and a different view or two went missing on every
  export (measured on the author's desktop: 3, 2 and 2 of 39 views per
  export with 1.10.0). Now a block counts as finished only when it holds
  more than styles, scripts, links, comments or whitespace, and none of the
  page's blocks has changed for 150 ms. With this release: 0 of 39 lost in
  three full exports.

## Changed behaviour

- A block that has not finished after 5 000 ms is reported once in the
  export log: `Plugin block <class> in <note> did not finish within 5000 ms
  (no output | still changing)`. It replaces upstream's `Plugin element …
  not rendered correctly!` on the main path. A block that draws nothing on
  purpose is reported as `no output`.
- An export takes longer where pages hold plugin blocks: measured on the
  author's vault, the page writes of a full export took 52–53 s instead of
  27 s.

## Breaking changes and migration

- None. Settings and plugin id are unchanged. Install `main.js`,
  `manifest.json` and `styles.css` into
  `.obsidian/plugins/webpage-html-export/`. Clear the plugin's cache before
  the first export, so pages exported with 1.10.0 are written again.
