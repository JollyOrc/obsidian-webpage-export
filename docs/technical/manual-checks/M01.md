`~/Downloads/roa-export-diag/diag-1.9.2.patch`; logging only).
**Runs in:** the vault `Raiders of Arismyth Rules`, plugin folder
`.obsidian/plugins/webpage-html-export/`.
**Purpose:** measure where and why the export fails before US-002 states a
cause (SCAR-024). Not a story check; nothing is accepted or rejected here.

## Steps

1. Restart Obsidian (or disable and enable "Webpage HTML Export").
2. Settings → Community plugins: the plugin shows version **`1.9.2-diag.1`**.
   If it shows `1.9.2`, stop: the old build is loaded. Do not accept an
   offered update during this check.
3. In the plugin settings set the log level to **All**.
4. Export the current selection exactly as usual (same export folder).
   Note the wall-clock time from start to end, and anything you see (error
   pop-ups, a hang, Obsidian freezing).
5. Wait 30 seconds after the export ends (late events are still written).
6. Settings → Webpage HTML Export → the bug icon ("debug info"): paste the
   clipboard into `~/Downloads/roa-export-diag/debug-info.txt`.
7. Tell Claude the check is done. The timing log is the newest
   `~/Downloads/roa-export-diag/diag-*.tsv`.

## What a correct run shows

- The export behaves as it does with `1.9.2` (same files, same failures, if
  any); the diagnostic build changes no behaviour, but its block watcher polls
  the DOM every 16 ms, which may slow rendering slightly.
- The TSV has a `batch start` line naming `version 1.9.2-diag.1`, one
  `file start` and one `file ok|failed` line per exported file, and lines
  `block:text-mapper` for the 13 maps in the selection.

## Result (2026-10-30, run 1)

Log: `~/Downloads/roa-export-diag/diag-2026-10-30T10-50-43-193Z.tsv`
(1 629 lines). No `debug-info.txt`: the user force-quit Obsidian after about
5 minutes without a response.

Measured:

- 227 files started, 226 finished `ok` within 49.5 s; slowest 536 ms
  (`1.3.1 Combat.md`); no `failRender`, no other timeout.
- Text Mapper blocks reached: 2, both filled (`1.4.1 Combat Skill
  Branches.md` 105 ms, `Elemental Magic Spells.md` 51 ms). The other 11 were
  not reached.
- `Rulebook/Texts/01 Player Section/1.4.3 Magic Skills.md`: main renderer
  `sections-counted` timed out (4 002 ms of 4 000), the fallback renderer ran;
  after 15 fallback sections the log stops (last line at 49 506 ms). Not one
  later line, not even the 30 s late watchers (timers), so the main thread
  stopped running JavaScript: a freeze, not a slow wait.
- That note has 31 lines: 8 heading embeds of `1.3.2 Magic.md` and 8 embeds
  of the spell-school notes, each with one `text-mapper` block, written as
  Markdown links (`![Body Magic Spells](../../Detail%20Bits/...md)`).
- The export folder `~/Downloads/RoA Export` was not changed (0 of 546 files
  newer than the run).

Not established (SCAR-024): which call freezes (section render, measure,
post-process or the canvas step of the fallback loop), and whether the
freeze needs the maps inside embeds, the heading embeds, or only the
fallback renderer. The diag build differs from the installed release in its
toolchain and polls the DOM every 16 ms.

Defect of the instrument (SCAR-008): fallback sections have no
`lineStart`/`lineEnd` in this Obsidian version; the labels read
`undefined-undefined`. Block lines for the frozen file were never written,
because they are written when the file finishes.
