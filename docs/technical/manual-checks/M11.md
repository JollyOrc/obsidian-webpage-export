# M11 — #12: why a dataviewjs view's output is missing from some exported pages

**Build:** the release `1.10.0` (`main.js` `e64a7a36…`), unchanged. The
instrument is in the vault, not in the plugin: the author's statblock view
(a `dv.view` script used by about 40 notes) replaced by a diagnostic copy,
version `issue12-diag.1`, that behaves and draws exactly as the original and
appends one JSON line per step to
`~/Downloads/roa-export-diag/2026-11-11-issue12/view-log.jsonl`.
**Runs in:** the author's working vault `Raiders of Arismyth Rules`, exporting
with the "Online website" preset to the usual export folder.
**Purpose:** G0 measurement for #12, before any story (SCAR-045: the failure
is seen only on the desktop). It decides between two explanations, both
unverified (SCAR-024):

- **A — copied early:** the off-screen render's wait ends when no
  `block-language-*` element is empty (`render-api.ts`, `renderDetached`);
  `dv.view` puts the view's CSS into the block before its script runs, so the
  block may count as filled while the script has not drawn yet.
- **B — no page yet:** `dv.current()` returns nothing for the note in the
  off-screen render (Dataview's index not ready), and the view returns
  without drawing.

The log tells them apart: a note missing from the export whose log shows the
view's `root` step or later in the export's render is A; one whose log shows
`current` with `page: false` is B.

## What a correct result looks like

For each run: the number of pages without the view's output, and for each
such page its class from the log. A run with no missing page is a valid
result and is recorded as such; the instrument may change the timing it
measures (SCAR-028), which is itself a finding.
