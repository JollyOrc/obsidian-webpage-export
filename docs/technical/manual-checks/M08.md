## Result (2026-10-30, run 1)

The user started at about 21:04 local; the export **finished within a
minute — no freeze** (log `diag-2026-10-30T20-04-05-750Z.tsv`: 331 notes
detached-start and detached-done, 31 heartbeats, none late). All files were
written. `1.4.3-magic-skills.html` looks fine (user). But pages of notes with
frontmatter hold only their properties: `index.html` (screenshot: empty
page, no usable sidebar), the Creatures pages.

Measured by program: `index.html`'s document holds only the hidden
`<pre class="frontmatter">`; the sizer and the body are gone (log: `index.md`
rendered with 112 elements and copied). `orc-warrior.html`: 64 characters
(properties) against 886 in the August export.

Cause, from the code and the shape (consistent with every observation; to be
confirmed by the fix): `postProcessHTML` "move frontmatter before
markdown-preview-sizer" moves `.frontmatter` and removes its former parent.
In the preview that parent is the frontmatter's own section wrapper; the
detached renderer writes blocks without section wrappers, so the parent is
the sizer and the whole body is removed. The headless checks missed it: the
fixture has no note with frontmatter, and the vault-copy check looked only
at three pages without frontmatter (SCAR-015, SCAR-027).

The empty sidebar in the screenshot is a separate point: the file tree is
loaded by script from `site-lib/html/file-tree-content.html`, which a
browser may refuse over `file://`; not measured.
